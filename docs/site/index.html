CAPRA

Context-Aware Privacy Risk Assessment

A five-layer reference framework and working prototype that keeps privacy risk assessment continuously sensitive to the context in which data is used.

GitHub repo Videos Architecture

The problem

Modern socio-technical systems — hospitals, retailers, universities — collect telemetry whose privacy implications shift with context. The same data field can be low-risk in one setting and high-risk in another, but today's tools (DPIAs, static risk registers) treat risk as a fixed label. When context changes, the risk posture is already out of date.

The approach

CAPRA is developed under Peffers' Design Science Research Methodology across three evaluation domains: healthcare, retail, and student admission. Each domain runs the same architecture over domain-specific telemetry, and outputs are compared to expert-labelled ground truth and to a baseline static register.

The five-layer architecture

HIL

Human-in-the-Loop

Reviewer decisions and rationale are captured and written back into the ontology as labelled examples.

E&RL

Escalation & Response

Declarative policies: LOW/MED logged, HIGH alerted, CRITICAL escalated with full context bundle.

RIL

Risk Intelligence

Deterministic severity mapping (0/1/2/3+ contextual hits → LOW/MED/HIGH/CRIT). Writes to Loki and MongoDB Atlas.

CPL

Context Processing

OWL ontology in Fuseki + SPARQL derives contextual attributes. Optional LLM disambiguates free-text purpose.

DFL

Data Federation

Ingests Kafka, HTTP, CDC. Normalises into a common envelope: actor · action · resource · purpose · timestamp.

The prototype

  • Workflow engine: n8n
  • Ontology store: Apache Jena Fuseki (OWL + SPARQL)
  • Durable store: MongoDB Atlas
  • Streaming: Apache Kafka
  • Observability: Grafana Cloud + Loki
  • Optional LLM: Azure OpenAI

Set-up instructions for external reviewers are in docs/SETUP.md. A reference docker-compose.yml is provided.

Evaluation status

Beta iteration complete. 396 telemetry records processed across three domains. Full evaluation matrix, per-layer reports, and DSRM alignment are in test_artefacts/.
